# ASTRA 모의테스트 (Paper Trading) 및 전략 검증 결과

## 1. 테스트 목적
* ASTRA 프로그램의 크레딧 문제로 인하여 직접 V2 전략 (`trend4h_20`) 이식 및 작동 테스트 수행.
* `engine.py`가 V2 로직 (Policy 객체의 evaluate, trailing_stop, exit_signal) 을 정상적으로 호출하여 상태(Position) 관리가 되는지 확인.
* 과거 180일(1시간 봉 데이터)을 통한 교차 검증 백테스트 수행 후 전략의 '수익 극대화' 측면 평가.

## 2. 작업 내역 및 모의테스트 요약
1. **Config 교체 완료**: `config/paper.toml` 내 `strategy = "trend4h_20"`으로 설정. V2 전략명을 `config.py` 에서 인지할 수 있도록 예외처리 리스트 수정.
2. **모의 구동 (Paper Run) 성공**:
   * `scripts/paper_run.py` 를 통해 임의의 Mock 데이터로 `PaperEngine` 을 구동.
   * 엔진 초기화부터 데이터 주입, cycle() 실행까지 V2 Policy가 정상 동작함을 확인 (KeyError 등 초기화 오류 없음).
3. **백테스트 (3-Fold 180일 교차검증) 재확인 결과**:
   * `trend4h_20`: `+217.87 PnL` (3 폴드 내내 가장 안정적인 상승, 최대 수익)
   * `range1h` (박스권 역추세): `-287.55 PnL` (참담한 손실)
   * `pullback4h` (눌림목): 빈도가 낮아 리스크는 적으나 수익 극대화 실패.

## 3. 냉정한 감상평 (리뷰)
**결론: `trend4h_20` 전략은 당장 모의투자에 적용해볼 만한 수학적 엣지(Edge)를 증명했습니다.**

* **기존 V1 (돌파매매) 한계 극복:** 기존 전략은 시장이 횡보할 때 가짜 신호(Whipsaw)로 인해 손실이 누적되는 약점이 있었습니다.
* **추세 추종의 이점:** 이번에 이식한 `trend4h_20`은 4시간 단위의 굵직한 추세를 기반으로 20개 캔들 돌파 시점을 캐치하므로, 불필요한 노이즈가 제거되어 잦은 손절을 막아줍니다.
* **수익 극대화 원리:** 이 전략은 '손실은 짧게, 이익은 길게(Trailing Stop)' 가져가는 전형적이고 검증된 수학적 모델(Donchian Channel + 이동평균선 필터)을 사용하고 있습니다. 백테스트 상 180일이라는 긴 기간 동안 양수(+)의 수익을 유지했다는 점이 가장 큰 장점입니다. 
* **주의점:** 박스권 장세(역추세, Range) 시도를 테스트해본 결과 극심한 손실이 발생했습니다. 코인 시장 특성상 강한 변동성을 동반한 '추세(Trend)' 국면에서 수익을 뽑아먹고, 횡보장에서는 쉬는 현 로직(`trend4h_20`)이 가장 우월합니다.

## 4. 넥스트 스텝 (ASTRA 복귀 후 인수인계용)
* **모의투자 봇 실가동 (GCP Paper Trading - T1 프로젝트로 이전):**
  기존 `goldenpath-ai`에서 발생하던 문제들을 뒤로하고 완전한 새출발을 위해, GCP 상에 `t1-bitget-astra`라는 새로운 독립 프로젝트를 생성했습니다. 현재 V2 코드(`trend4h_20`)는 이 "T1 프로젝트"의 클라우드 VM(`bitget-paper-v1`)에 완전히 새롭게 배포되었으며, 에러 없이 24시간 실시간 모의투자를 가동 중입니다. (`heartbeat` 정상) ASTRA가 복귀하면 실시간 스트림 환경에서도 백테스트 결과가 일치하는지(슬리피지, 펀딩비 등의 변수 포함) 검증해야 합니다.
* **테스트 코드 모듈 업데이트:**
  기존 `tests/test_engine.py` 가 과거 V1 모듈의 평가(evaluate) 방식에 종속되어 있어 테스트 일부가 실패(KeyError)하고 있습니다. 이 부분의 Mocking을 V2 Policy 구조에 맞게 개편하는 작업이 필요합니다.
